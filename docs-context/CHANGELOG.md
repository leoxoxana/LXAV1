## 2026-10-03 (latest) - Sessions survive concurrent requests of other devices (commit f8dd0ef)
- Owner (iPhone installed app, admin #1 Leo): still logged out when closing and reopening the app.
- Cause (found by reading functions/lxa-account.js + reproduced by session-race.test.js, 2 of 3 tests failing before the fix): save(account) ran updateAccount(key, () => plain()), i.e. it REPLACED the stored account with the object read at the start of the request, ignoring the value Firebase hands to the transaction. Any request (silent restore, spin, AUTO, logout) that read the account before another device's login and saved after it wrote back a sessions list without the new token. That device then got 401 "Session expired" at its next restore and the client cleared its token. More devices / AUTO running = more windows for it (iPhone app + iPad tab + PC).
- Fix: issueSession / revokeSession / revokeAllSessions also record operations (non-enumerable __sessionOps); save() calls plain(current) and mergeSessions(current, account, ops) replays them on the account as stored at commit time (Firebase retries mutate with the current value). A node that does not exist yet (rename) starts from the account object. Admin password edit pushes a 'clear' op. MAX_SESSIONS 8 -> 25.
- Tests: session-race.test.js (silent restore vs concurrent login, logout vs concurrent login, password change revokes all, 12 later logins keep an earlier device); suite 97 tests; e2e login/AUTO/logout 21/21.
- Limits: not verified against the real Firebase; sessions already erased cannot be recovered: one more login after the deploy is needed (then it stays). iOS can still clear a Safari TAB's storage after 7 days without use (installed apps are exempt). NOT deployed.
