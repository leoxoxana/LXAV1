## 2026-10-04 - Radio health: strict probe, periodic re-check, player reports, hide list (commit cf3c565 + 83c8343; renderer v=421, layout-fix v=488, radio.js v=8)
- Owner: radios that do not play (Radio Marketescu Rap&Trap) -> "yes" to the package: simple and compact on the surface, advanced and professional underneath. Brainstorm items 1-5 done; item 6 (auto-hide after 3 devices / 24 h) deliberately NOT built yet (wait for real report volume; reports are public input, so they only inform the owner).
- 1. STRICT PROBE (functions/radio.js probeStream): a station must deliver audio to a plain request AND to a phone-style request (iPhone UA, Range bytes=0-, icy-metadata:1); the phone request runs only after the plain one passed (one connection at a time, small hosts limit listeners). A body that starts with "<" is a web page, not audio. On the live list 6 of 220 stations answered a phone with a web page / nothing (Radio Pro Manele, Radio Noise Party, Replica Radio Rock, RadioClick, ...).
- 2. RE-CHECK (recheckList + getList recheck): a client that sees a list whose last check is older than 3 h calls /api/radio?recheck=1 once per page load; the SERVER decides (it re-checks only if checkedAt is older than 3 h, one run at a time, 22 s budget): every listed station is probed again (second chance, 8 at a time), dead ones leave the list (kept in `dropped`, max 40, admin only), `checkedAt` stored in meta/radio. More than 40 % dead at once = our own network: nothing removed. Unprobed (budget) stations stay. Nothing is ever added by a re-check. The answer is no-store and replaces the list on the phone; the full rebuild (12 h / deploy / cron) is unchanged.
- 3. AUTOMATIC REPORT (radio.js sendReport): after a station failed twice in a row on the device (retry, then skip) the player POSTs an anonymous report {action, u, kind:'auto', code (e1..e4 = MediaError, timeout, stall, reject), dev (random 20-hex id kept only in localStorage lxa-radio-dev-v1), net (effectiveType), ms (time to failure), ns / rs (networkState / readyState)}. No account, no name. Once per station and kind per 6 h per device (lxa-radio-rep-v1).
- 4. THE FLAG (small button in the bar, hidden until a station is chosen): "does not work for me" (also: silent / wrong thing). Sends kind:'manual' with code 'playing' / 'loading' / 'nostart', dims the station on this device for 24 h, shows "Danke - gemeldet" for 2.5 s and moves on in the direction the listener was going (pauses if there is no other good station).
- Server (functions/radio-reports.js + POST in functions/radio.js): body <= 1500 bytes, url must be https AND in the current list (the node count stays bounded), device id hashed (sha1, 12 hex), platform from the User-Agent (ios / android / mobile / desktop), 30 reports / hour / device (per instance), same device + same kind within 10 min counts once, 40 devices kept per station. Stored in Firebase radioReports/<sha1(url)[0..16]> (transaction). 404 unknown station, 400 junk, 413 too large, 429 limit.
- 5. ADMIN > RADIO (action admin-radio, admin + password like every admin action; ops list / hide / unhide / clear / test): most reported stations first (distinct devices, count, auto / manual, reasons, platforms, last time), list of hidden stations, stations the re-check removed, last check time and station count. Buttons per row: magnifier = probe now with both request styles (shows the reason: http 403, type text/html, timeout ...), hide (stored in meta/radioHide/<key>, applied when the list is SERVED: no rebuild, no deploy; takes up to 30 s per instance + the 5-minute CDN cache), unhide, delete the reports.
- Honest limits: a stream that is silent or plays the wrong thing cannot be detected from the browser (cross-origin audio cannot be read): only the flag finds that. A phone on a network that blocks a host cannot be detected by the server: the report (code e2 / e4 + platform) is the evidence.
- BUILDER_VERSION changes with this deploy (hash of functions/radio.js): the first request after the deploy rebuilds the list with the strict probe (about 30 s, then cached 12 h). If the build is slow the owner can open /api/radio?refresh=1 once.
- Tests: radio-health.test.js (29): probe (headers, web page for the phone, no second connection after a failed first, "<" body, diagnose), re-check (removal, flaky stays, 40 % rule, budget), getList re-check (due / not due / single run / failing), report validation + counting + limits + summary, handler POST/GET/hide, admin actions. radio.test.js adapted (POST = report). Browser: e2e_radio4 15/15 (re-check asked once and applied, auto report after two failures with code, anonymous body, flag button + thanks line + dimming + move on, real server stores 2 devices and refuses an unknown station, admin hub > RADIO lists the station, test button, hide -> gone from the served list, unhide).
- Rollback: git revert this commit (the Firebase nodes radioReports / meta/radioHide are simply ignored).
- NOT deployed. Not verified on a real phone: the flag button size on small screens was checked in the browser only.

Now three titled groups: GAME (RTP, custom chances, payouts, jackpot, wild), PLAYERS & LEADERBOARD (players, then the destructive leaderboard reset last, tinted red), RADIO (station reports).
